# SafeWall dashboard — kontekst pracy

- Oficjalne logo projektu to **4A**: dwukolorowy mur z trzema blankami. Źródło: `../brand/svg/safewall-logo.svg`; eksporty: `../brand/`. `npm run build` synchronizuje logo i favikony do `dist/` oraz osadza je w samodzielnym `Podglad.html`. W nagłówku używaj SVG bez gradientowego kafelka; favicon SVG/ICO jest przezroczysty, a ikona Apple 180 px ma nieprzezroczyste grafitowe tło. Ikony Lucide sygnalizujące stan ochrony zachowują własne znaczenie.

- Ten projekt dotyczy lokalnego dashboardu SafeWall. CAD/obudowa i diagnostyka modemu są oddzielnymi zadaniami.
- Wzorzec wyglądu to https://rainbowkit.com, ponownie obejrzany w Playwright na komputerze i telefonie. Czarne tło, zaokrąglona systemowa typografia, mocne nagłówki, grafitowe panele, spójne liniowe ikony Lucide w stonowanych kolorach i niebiesko-fioletowy przycisk. Przegląd ma jeden panel dzielony na ochronę i jakość połączenia oraz drugi łączący statystyki z wykresem. Utrzymuj te grupy, czytelną hierarchię i mało tekstu. Zachowuj własną identyfikację SafeWall.
- Przegląd eksponuje stan ochrony (Tor, blokada poza Torem, DNS, czas odczytu) i jakość połączenia (odpowiedź przez Tor, sygnał LTE, zerwania w ostatniej godzinie). Transfer i statystyki DNS są niżej. Dostępność internetu i ochrona są niezależne: gotowy Tor nie zastępuje testu odpowiedzi. Szczegółowe pomiary są w zakładkach lub rozwijanych sekcjach. Interfejs ma działać na telefonie i komputerze, także bez internetu oraz z klawiaturą.
- Pierwszy ekran przeglądu obejmuje górny pasek, nawigację, nagłówek i panel ochrony/połączenia. Na komputerze zajmuje wysokość viewporta; statystyki zaczynają się po przewinięciu. `.view-intro` używa `100svh` pomniejszonego o mierzoną wysokość paska. Przy małych ekranach lub dużym tekście może rosnąć, żeby nie ucinać odczytów. Panel ochrony jest renderowany w `#overview-health` i czyszczony przy błędzie API oraz zmianie zakładki.
- Użytkownik odrzucił dekoracyjny schemat pojedynczego obwodu Tor jako mało informacyjny. Został usunięty. Nie przywracaj go jako wizualizacji całego routera; przyszła diagnostyka obwodów musi wynikać z rzeczywistych pomiarów i uwzględniać wiele obwodów oraz przypisanie strumieni TCP.
- Obecnie działają mocki; kolejnym etapem będzie wdrożenie na Raspberry Pi z prawdziwymi pomiarami. Docelowa nazwa: `safewall.local`.
- Domyślnie nie publikuj panelu do internetu i nie zmieniaj Pi, DNS ani makiety Tor Check. Wdrożenie na urządzeniu wymaga nowego polecenia dotyczącego tego etapu.
- Zachowuj jeden wyraźny znacznik „Dane demo” w nagłówku. Na życzenie użytkownika nie powtarzaj informacji o symulacji w kafelkach, stopkach ani przyciskach. Ikony interfejsu pochodzą z lokalnego zestawu Lucide 1.51.0 w dist/app.js. Użytkownik odrzucił gradientowe kafelki ikon, wielowarstwową tarczę i nakładany symbol pulsu; nie przywracaj tych dekoracji. Zachowuj jeden styl kreski i warianty odpowiadające stanom danych (ochrona, blokada, nieznany stan i poziom LTE). Adapter API nigdy nie przechodzi automatycznie na mocki po błędzie; niewiadome pomiary pozostają nieznane.
- Źródła są w `dist/`; `Podglad.html` powstaje przez `npm run build`. Projekt nie wymaga pobierania zależności.
- Przed przekazaniem zmian: `npm run check`, `npm run build`, `npm test`. Testy przeglądarkowe tylko gdy środowisko pozwala uruchomić przeglądarkę.
